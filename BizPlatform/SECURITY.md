# אבטחת מידע – BizPlatform

## מה מיושם
| תחום | מימוש |
|---|---|
| **סיסמאות** | Argon2id (פרמטרי OWASP); מינימום 12 תווים + מורכבות + חסימת סיסמאות נפוצות; חובת החלפה בכניסה ראשונה |
| **אימות דו-שלבי** | TOTP (Google/Microsoft Authenticator); ניתן לחייב לכל המשתמשים (`BIZ_REQUIRE_2FA=true`, ברירת מחדל בהתקנה) |
| **Brute force** | נעילת חשבון אחרי 5 כישלונות ל-15 דק'; הגבלת קצב לפי IP ולפי משתמש; הודעת שגיאה אחידה (אין חשיפת משתמשים קיימים) |
| **Sessions** | בצד שרת, ניתנים לביטול; עוגייה HttpOnly + Secure + SameSite=Strict; רק SHA-256 של הטוקן נשמר; ניתוק אחרי 30 דק' חוסר פעילות / 12 שעות; ביטול כל ה-sessions בשינוי סיסמה/תפקיד/השבתה |
| **CSRF** | Synchronizer token בכל בקשה משנה + SameSite=Strict |
| **הרשאות (RBAC)** | 7 תפקידים, מינימום הרשאות, נאכף בשרת על כל endpoint; הגנה מהסרת המנהל האחרון |
| **Need-to-know** | ת.ז עובדים – רק HR/מנהל; מפתחות רישיון – רק IT/מנהל, וכל צפייה נרשמת ביומן |
| **הצפנה במנוחה** | ת.ז, מפתחות רישיון וסודות 2FA מוצפנים ברמת עמודה (Fernet: AES + HMAC) |
| **הצפנה בתעבורה** | HTTPS בלבד (Caddy + Let's Encrypt אוטומטי), HSTS |
| **יומן ביקורת** | כל פעולה (כולל כניסות, ייצוא, צפייה בסודות) נרשמת עם משתמש, IP וזמן; שרשרת Hash – כל שינוי/מחיקה של רשומה מזוהה ("בדיקת שלמות"); סיסמאות/סודות לעולם לא נרשמים |
| **OWASP Top 10** | ORM עם פרמטרים (SQLi); React escaping + CSP קפדני (XSS); ולידציה מחמירה עם `extra=forbid` (mass assignment); הגבלת גודל בקשה; אין stack traces ללקוח; תיעוד API כבוי בייצור |
| **CSV/Excel injection** | נטרול תאים שמתחילים ב- `= + - @` |
| **כותרות אבטחה** | CSP, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy, COOP/CORP |
| **תשתית** | מסד הנתונים ברשת פנימית בלבד; קונטיינרים ללא root, read-only, `cap_drop: ALL`, `no-new-privileges`; סודות אקראיים נוצרים ב-`setup.sh` ולא נשמרים בקוד |
| **גיבויים** | `pg_dump` יומי מוצפן AES-256 (PBKDF2 600K), שמירה 30 יום, סקריפט שחזור |
| **שרשרת אספקה** | גרסאות נעולות; CI מריץ pip-audit, npm audit, bandit ו-gitleaks; Dependabot שבועי |

## חובות המפעיל (חשוב!)
1. לשמור את `BIZ_ENCRYPTION_KEY` ו-`BACKUP_PASSPHRASE` במנהל סיסמאות. בלעדיהם אין שחזור.
2. להעתיק את תיקיית `backups/` למיקום נוסף (כונן חיצוני / ענן) – כלל 3-2-1.
3. לבדוק שחזור גיבוי לפחות פעם ברבעון.
4. לעדכן: `git pull && docker compose up -d --build` כשמגיע עדכון אבטחה.
5. לסקור את יומן הביקורת ואת רשימת המשתמשים מדי חודש; להשבית משתמשים שעזבו מיד.
6. בהתקנה בענן – לפתוח בחומת האש רק פורטים 80/443 (ו-SSH עם מפתח בלבד).
